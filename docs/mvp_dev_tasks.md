# MVP 开发任务清单: 账号急诊室

## 1. 开发目标

完成一个可上线验证的“小红书 AI 账号诊断与选题生成器”MVP。

核心闭环：

```text
首页 -> 诊断表单 -> AI 生成 -> 免费报告 -> 留资解锁 -> 完整报告
```

第一版不做登录、不做自动支付、不做 PDF 导出，优先验证用户是否愿意提交账号信息、查看报告并留资。

## 2. 推荐技术方案

默认方案：
- 前端框架：Next.js
- UI：Tailwind CSS
- 后端：Next.js API Routes
- 数据存储：SQLite 或 Supabase
- AI 接口：DeepSeek API
- 部署：GitHub Pages 或自有静态资源服务

如果目标是最快本地跑通，可先用：
- Vite + React
- Node/Express
- SQLite

## 3. 里程碑

### M1: 静态页面闭环

目标：没有 AI 和数据库时，用户也能走完前端流程。

产出：
- 首页
- 诊断表单页
- 生成等待页
- 免费报告页 mock
- 留资弹窗
- 完整报告页 mock

### M2: 数据与 API 闭环

目标：表单提交后能创建诊断记录，并保存报告结果。

产出：
- 诊断创建接口
- 报告查询接口
- 留资接口
- 本地数据库表

### M3: AI 生成闭环

目标：提交表单后真实调用 AI 生成报告。

产出：
- Prompt 模板
- AI 调用服务
- JSON 结构化解析
- 生成失败重试

### M4: 上线验证

目标：可以发到小红书/抖音做第一轮引流。

产出：
- 移动端适配
- 基础埋点
- 错误日志
- 部署配置
- 隐私说明

## 9. 风险与处理

### 9.1 AI 输出空泛

处理：
- 增强 Prompt，要求结合用户输入逐条诊断
- 输出前做字段完整性检查
- 准备几个高质量示例作为 few-shot

### 9.2 生成时间太长

处理：
- 等待页展示动态步骤
- 先生成免费报告，再后台生成完整报告
- 减少一次输出长度，必要时拆两次 AI 调用

### 9.3 用户不愿意留微信

处理：
- 免费报告给得更具体
- 解锁模块明确完整报告价值
- 测试“直接展示完整报告 + 底部引导加微信人工精修”

### 9.4 内容平台引流弱

处理：
- 多做前后对比类内容
- 用真实账号案例展示诊断结果
- 评论区关键词引导
- 优先投放“标题诊断”和“选题生成”这种更具体的钩子
